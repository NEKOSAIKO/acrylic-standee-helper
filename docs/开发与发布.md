# 开发与发布

普通使用者直接下载 Releases 的 Mac ZIP，无需编译。

## 开发

```sh
git clone https://github.com/NEKOSAIKO/acrylic-standee-helper.git
cd acrylic-standee-helper
zsh scripts/build-app.sh
```

构建产物为 `dist/亚克力立牌助手 0.2.app`。构建脚本自动读取本机 SDK，不依赖原作者的目录。需在 Apple Silicon Mac 上安装 Xcode Command Line Tools 和 Python 3。

- `src/`：Swift 界面、几何、白墨、PDF 和 Illustrator 脚本。
- `assets/`：图标与内置示例。
- `vendor/Clipper2/`：几何计算依赖及许可证。
- `scripts/`：构建、打包与发布。
- `docs/`：用户教程及界面图片。

## 已验证的构建环境

本次在 Apple Silicon Mac、Swift 6.0.3（Swift 5 模式）、macOS 14.5 SDK 下完成独立构建与内置示例检查。当前电脑的默认 15.2 SDK 构建未完成验证。

可用 `SDKROOT` 指定已安装的 SDK；若本机需要 Swift 模块映射兼容配置，可用 `SWIFT_VFS_OVERLAY` 指定本地 VFS overlay 文件。通常的 Xcode 安装先尝试默认构建命令。仓库不包含作者电脑的绝对路径。

## 获取与提交更新

`git pull --ff-only` 将 GitHub 上的更新拉到本地；`git push` 将已提交的本地更改推到 GitHub。其他贡献者可以 Fork 后提交 Pull Request。

```sh
git pull --ff-only
# 修改源码，构建并检查界面
git add src scripts docs README.md CHANGELOG.md
git commit -m "描述这次改动"
git push origin main
```

不要提交客户原图、生产文件、本地账号信息或构建缓存。

## 发布新版

1. 修改 `scripts/build-app.sh` 中的版本号与构建号，以及 `src/main.swift`、`src/FactorySheet.swift` 的版本文字。同步使用说明和 `CHANGELOG.md`。
2. 构建并检查本次涉及的功能，然后提交并推送所有源码改动。
3. 写好该版本的更新说明文件，例如 `docs/releases/0.2.8.md`，提交并推送。
4. 使用已登录且有仓库写权限的 GitHub CLI 运行：

```sh
zsh scripts/release.sh 0.2.8 docs/releases/0.2.8.md
```

脚本会重新构建，确认版本号、干净工作区及远端源码一致，生成 ZIP 和 SHA-256 校验文件，再创建标签、上传到草稿 Release，最后发布为最新版。旧版不会覆盖。首页下载入口无需修改。

若网络中断，先检查 GitHub 上同名标签和草稿 Release；脚本不会覆盖已有版本。可在对应草稿中补齐附件后手动发布。

发布机制参考：[GitHub Releases 官方说明](https://docs.github.com/en/repositories/releasing-projects-on-github)、[GitHub CLI 发布命令](https://cli.github.com/manual/gh_release_create)。

当前构建采用 ad-hoc 本地签名，不包含开发者证书或 Apple 公证。正式公证需要维护者自己的 Apple Developer 账号及签名配置。
